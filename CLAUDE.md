# Card Vault (crd)

Private, single-owner web app for scanning, indexing and valuing a sports card
collection from a phone. Owner is not a developer: plain language in all UI text.

## Stack
Next.js 16 (App Router, `src/`), React 19, TypeScript, Tailwind 4, SQLite
(better-sqlite3 + Drizzle), iron-session, sharp, zod, Anthropic SDK, Vitest.

## Commands
- `npm run dev` start locally (needs `.env.local`, see `.env.example`)
- `npm run check` lint + typecheck + tests (run before every commit)
- `npm run build` production build
- `npm run db:generate` create a migration after editing `src/db/schema.ts`

## Conventions
- This Next.js is newer than most training data. Read the matching guide in
  `node_modules/next/dist/docs/` before using a framework feature. Middleware is
  now `src/proxy.ts`. `cookies()`, `headers()`, `params`, `searchParams` are async.
- `cacheComponents` is off on purpose; pages render per request.
- Database: only through Drizzle (`getDb()` from `@/db`). No string-built SQL.
  Value lists and types come from `src/db/schema.ts`. Migrations apply on startup.
- Money is whole US cents in integers. Use `src/lib/money.ts`.
- Card recognition goes through the `Recognizer` contract in
  `src/lib/recognition/types.ts`. Default is free, keyless reading in
  `src/lib/free/` (owner rule: never require API keys). Paid AI stays off
  unless `RECOGNITION_MODE=anthropic`. Tests use sample mode or fakes; tests
  never touch the network.
- Screens: phone first (360px wide), use `src/components/ui.tsx` and the color
  tokens in `globals.css` (no raw hex), 44px tap targets, labeled controls.
- Every page and API route except `/login` requires the owner session.
- All outside input is validated with zod. Uploaded photos are re-encoded by
  sharp; file names are generated by the server.
- Secrets live only in `.env.local` or host settings. Never log them.
- Exact dependency versions. No new dependency without a stated reason.
- No em dashes or en dashes in UI text or docs (owner preference).
