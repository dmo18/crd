Server "appy" · Card Vault

Set up your server, one click at a time

14 steps. Each one says where you are, exactly what to click or type, and what you should see before moving on. About 90 minutes, most of it waiting.

What is automatic and what is yours

One pasted command does all this

  • Updates Ubuntu and closes every door to the internet
  • Connects the server to Cloudflare
  • Installs Coolify (the dashboard that runs your apps)
  • Security patches, log limits, weekly security check
  • Backup tool, alert tool, health check, help report

You click through these

  • Create the machine in Hyper-V and install Ubuntu
  • Cloudflare: one tunnel, two sign-in rules, four routes
  • Answer a few questions the tools ask
  • Coolify: add Card Vault and press Deploy

About the pictures: they are drawings of each screen, not photos. I cannot sign in to your Cloudflare, Hyper-V or Coolify to photograph them. Buttons are where I show them, but a label may be worded slightly differently. If a screen does not match, send me a screenshot and I will tell you what to click.

1

Download Ubuntu

On your Hyper-V host5 min
  1. On the Hyper-V host, open a browser and go to ubuntu.com/download/server.
  2. Choose Ubuntu Server 24.04 LTS (not 26.04; the setup is built for 24.04) and download it. You get a file ending in .iso.

You should have: a file like ubuntu-24.04.x-live-server-amd64.iso in Downloads.

2

Create the machine "appy"

Hyper-V Manager10 min
  1. Open Hyper-V Manager. On the right, click New then Virtual Machine.
  2. Fill the wizard exactly like the picture, pressing Next between pages, then Finish.
  3. Right-click appy, choose Settings, and change the three things in the second picture. Click OK.

Still won't boot? Turn the machine off, open Settings, Security, untick Enable Secure Boot, click OK and start it again. That is fine for appy: it has no open ports and sits behind Cloudflare.

You should see: appy in the list, State "Off".

3

  1. Right-click appy, Connect, then click Start. A black window opens: this is the console.
  2. Press Enter on "Try or Install Ubuntu Server". Use arrow keys and Enter for everything below.
  3. Answer each screen like this table. Where it says "Done", just move to Done and press Enter.

4

Create the tunnel and copy its token

Cloudflare, in a browser on the Hyper-V host5 min

The tunnel is the private line between Cloudflare and appy. Do this in a browser on the Hyper-V host, so you can paste into the console in the next step.

  1. Go to one.dash.cloudflare.com and sign in. (First time: it asks you to pick a team name and the Free plan.)
  2. Left menu: Networks then Tunnels. Click Create a tunnel.
  3. Choose Cloudflared. Name it appy. Click Save tunnel.
  4. A page shows an install command. Do not run it. Find the long text starting with eyJ and copy only that. Paste it into Notepad for a minute.
  5. Leave this browser tab open.

You should have: the token (starts with eyJ, about 180 characters) in Notepad.

5

Run the automatic setup

Hyper-V console windowAutomated20 min

This is the one command that does the heavy lifting. You cannot paste into the console with Ctrl+V; use the menu instead.

No subdomain needed yet. The command only notes down the name appy.. Cloudflare creates the subdomains later, in step 7, when you save the routes.

  1. Press Copy below.
  2. In the console window's top menu click Clipboard then Type clipboard text. Wait while it types, then press Enter.
  3. It asks for your Ubuntu password (from step 3). Type it, Enter.
  4. Answer its questions as in the picture. For the token you can copy Cloudflare's whole sudo cloudflared service install eyJ... line: the setup picks the token out. It is saved at once, so if you ever run this again you only press Enter there.
cd ~ && rm -rf crd-main && curl -fsSL https://github.com/dmo18/crd/archive/refs/heads/main.tar.gz | tar xz && cd crd-main/infra/ubuntu && sudo bash bootstrap.sh --cloudflare appy.

At the very end it prints a temporary Coolify password. Write it down or take a phone photo of the screen. You need it in step 9.

You should see: a summary ending with the temporary password. Back in the Cloudflare tab, the tunnel appy shows Healthy (refresh the page).

If it stops with "STOPPED:", the line after it says why in plain words. Fix that and run the same command again; it is safe to repeat.

Prefer PuTTY over the console? The setup turns off password logins over SSH. To allow PuTTY again from your own local network only (never the internet), type this in the console: curl -sL github.com/dmo18/crd/raw/main/lan-ssh | sudo bash. To turn it off: add -s off at the end.

6

Add the two sign-in rules

Cloudflare, any browser10 min

These rules put a Cloudflare login in front of your server's own pages. They come before the routes so nothing is ever open by accident. From here on you can use any computer.

How it works: an address with a sign-in rule asks for your email code first. An address without one is open to everyone. That is why your other sites on this domain, and Card Vault later, are not affected: they simply get no rule here.

  1. Zero Trust, left menu: Access controls, Applications. Click Add an application, choose Self-hosted.
  2. Fill it in from row 1 of the table, add the policy, save. Then the same for row 2.
#NameSubdomainPathPoliciesExtra
1Server dashboardappy(empty)Allow, your email. Bypass rules for your office internet are fine here.
2Browser SSHappy-ssh(empty)Allow, your email. No Bypass rules.Turn on Allow access through browser-based RDP, SSH, or VNC sessions, then protocol SSH

Row 2 must have no Bypass rule: the browser terminal logs you in with a certificate Cloudflare makes for the person who signed in. A Bypass skips the sign-in, so there is no certificate and the terminal refuses.

You should see: two applications in the list.

7

Add the four routes

Cloudflare10 min

Routes tell the tunnel which address goes to which part of appy. Cloudflare makes the DNS record for each one by itself.

  1. Networking, Tunnels, click appy, tab Routes.
  2. Click Add route, Published application, enter row 1. Save. Repeat for rows 2 to 4.
#SubdomainPathService URL
1appy^/app/http://127.0.0.1:6001
2appy^/terminal/wshttp://127.0.0.1:6002
3appy(empty)http://127.0.0.1:8000
4appy-ssh(empty)ssh://127.0.0.1:22

Never leave the subdomain empty: that is your main site's address. The routes with a path must stay above row 3 (the Order column; drag to fix).

You should see: open https://appy.. Cloudflare asks for your email and sends you a code. After the code, a Coolify login page appears.

If Cloudflare says a record for appy or appy-ssh already exists, delete the old record under DNS and save the route again. Each app you add later gets its own route (step 12 shows it for Card Vault).

8

Turn on the browser terminal

Cloudflare, then the console5 min

After this you can type commands to appy from any browser, with easy copy and paste, at https://appy-ssh.. No password is used: Cloudflare vouches for you.

  1. Zero Trust: Access controls, Service credentials, tab SSH (not "Service Tokens"), Add a certificate.
  2. In the top box Application, choose appy-ssh and click Generate certificate. Copy the public key (one long line starting ecdsa-sha2-nistp256). It is public, not a secret.
  3. On the server (PuTTY or the console), run the command below. When asked, paste the key, then Enter.
sudo server-ssh-ca set

You should see: open https://appy-ssh., sign in with the email code, type your Ubuntu username: a terminal opens in the browser. Use it for every command from now on (paste works normally there).

The username is the one you made in step 3 (for example owner), even if your email starts with something else.

9

Sign in to Coolify and lock it

https://appy.10 min
  1. Open https://appy.. Sign in with your email and the temporary password from step 5.
  2. Coolify shows welcome questions. When it asks about a server, choose This Machine (localhost). Accept the rest.
  3. Left menu Settings: set the three things in the picture and save.
  4. Top right, your Profile: change the password to a long one of your own, then turn on Two-factor authentication and save the recovery codes.
  5. In the browser terminal, run the cleanup command below.
sudo rm -f /root/coolify-first-login.txt && sudo sed -i '/^ROOT_USER_PASSWORD=/d' /data/coolify/source/.env

You should see: signing out and back in asks for your new password and a 6 digit code.

10

Turn on alerts to your phone

Browser terminalGuided5 min
  1. Decide where alerts go and get the one thing it needs:
    • Telegram: in Telegram, message @BotFather, send /newbot, follow it, copy the token it gives you. Then send your new bot any message.
    • Discord: your server, Server Settings, Integrations, Webhooks, New Webhook, Copy Webhook URL.
  2. Run the command and answer its questions (1 or 2, then paste).
sudo server-alert setup

You should see: a test message arrive on your phone.

11

Turn on backups

Browser terminalGuided10 min

Have your backup server's details ready: address, username, password, and a folder name. SFTP is best; FTPS also works.

  1. Run the first command and answer its questions.
  2. It shows a backup passphrase once. Save it in your password manager right then.
  3. Run the second command to make the first backup (a few minutes).
sudo server-backup setup
sudo server-backup run && sudo server-backup status

Without the passphrase, no backup can ever be opened. Not by you, not by me.

You should see: status says the last backup worked. From now on it runs every night around 02:30.

12

Add Card Vault

Coolify15 min
  1. In Coolify: Projects, + Add, name it Card Vault. Open it, + New Resource, Public Repository.
  2. Paste https://github.com/dmo18/crd, click Check repository. Set Build Pack to Docker Compose. Continue.
  3. On the app's page set the two things in the picture, then Save.
  4. Tab Environment Variables: add CLIENT_IP_HEADER with the value cf-connecting-ip.
  5. Click Deploy (top right) and wait 5 to 10 minutes.
  6. In Cloudflare, tunnel appy, Routes, Add route: subdomain cards, path empty, Service URL http://127.0.0.1:80. Do not add a sign-in rule for it: Card Vault has its own password.

You should see: the status turn green: "Running (healthy)".

If it fails, open the Logs tab, copy the last lines and send them to me.

13

Create your Card Vault password

Coolify, then your phone5 min
  1. In Coolify, Card Vault, Environment Variables: find SETUP_CODE, reveal it and copy the value.
  2. On your phone open https://cards.. Tap Set your password.
  3. Paste the setup code, type a password of 16 or more characters twice, save.
  4. Tap Scan and photograph a card. Front and back gives the best result.
  5. In your phone browser's menu choose Add to Home Screen.

You should see: your first card in Inventory. Under More, "Connection check" says the address matches.

Browser terminalAutomated2 min
sudo server-check

You should see: a list of PASS lines. A WARN line tells you in plain words what to do. If you are unsure about one, send it to me.

After setup: the five things you will ever need

WhenDo this
Something looks wrongRun sudo server-support, then sudo cat the file it names, and paste the text to Claude. Passwords are removed automatically.
Updates are waiting (an alert tells you)sudo server-update. It backs up first and asks before restarting. Nothing updates by itself except security patches.
Add another appCoolify, + New Resource, its GitHub address, Domain https://name.:PORT, Deploy. Then a tunnel route name to http://127.0.0.1:80. It is public unless you also add a sign-in rule for name (like step 6).
The server is lostRepeat steps 2, 3 and 5 on a new machine, then sudo server-backup restore-dr with your backup passphrase.
Locked out of everythingThe Hyper-V console (step 3) always works.

Also do once: in GitHub turn on two-factor sign-in, and on your backup server turn on snapshots or "add only" access, so a break-in on appy could not erase its own backups.
